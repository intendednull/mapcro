# 2026-11-08: Getting a replay in: finding the file, dropping it, honest messages

deadlock-api is at capacity, and for a brand-new match it resolves only 3 Steam lookups an hour
per address, so the auto-fetch often can't get a replay. Uploading your own file is the
dependable path, and the operator's concern was that people can't find their replay files. The
spec is §6b, "Getting a replay in" (and §6a's Upload and fetch lines). The commits are 1fbb916 and
2ad0e61.

## What changed

- **Where's my replay?** beside every upload. The first draft showed per-OS default paths
  with a Copy button and a Ctrl+L hint; the operator replaced it mid-way with steps through
  Steam, which also cover libraries on other drives. The labels are checked against the
  installed strings, opening exact files only: Deadlock's `citadel_gc_english.txt` has
  "Match History" and the download button `Citadel_Replay_Download` = "Replay" (it becomes
  "Watch Replay" once downloaded); Steam's `steamui_english-json.js` has "Properties...",
  "Installed Files" and "Browse...".
- **Drop** on the landing or on Player (when the match has no replay): one window-level
  listener set, an overlay while dragging, and every file drop caught so the tab never
  navigates away from a board.
- **Progress and Cancel.** The XHR reports bytes; the bar shows "212 / 504 MB". Cancel aborts
  it, and the server's upload slot drops the partial file. The host keeps its own upload as the
  truth while it runs, so a poll can't flip the chip to "none" mid-upload.
- **The landing hands off.** A replay dropped on the landing used to upload there, on a page
  with nothing to do, then load the board. Now the board opens at once without a page load
  (`core/nav.ts` makes App's link reactive) and uploads it, so the summary can be watched
  meanwhile. The board attaches the match only past the upload's first MiB, when the server has
  seen the header and shows the upload as under way: attaching earlier would start a fetch from
  Valve, and attaching a file that isn't a replay would keep a junk board.
- **Messages** in one table (`player/notice.ts`), each an outcome and an action, with Try again
  and Upload replay file where they apply. The landing no longer makes a board for a match
  deadlock-api doesn't know: it says "Match not found yet." and keeps the id.

## Surprises

- **Boards remember themselves.** Any board you open goes into "Your boards" (Board.tsx sets
  it with the title). With the handoff, a landing upload that the server refused as not a
  replay still left its board listed, which broke the "a failed Open match isn't kept" check.
  The landing now reads the file's first 8 bytes (`PBDEMS2\0`) before making a board; Player
  does the same, so a wrong file is refused before it uses an upload slot.
- **A race between two answers.** On a handed-off upload of a match deadlock-api doesn't know,
  the upload's refusal and the metadata's 404 come back in either order. The metadata's used to
  win and the board said "Match not found yet." for a file that wasn't a replay. An upload's
  failure now wins.
- **The real worker exits silently** if it starts before the server has made the queue's
  directories. The real-replay e2e starts it after the server.

## Verified

- `e2e/upload-ux.spec.ts`: the steps (landing at 1280, 1440 and 390; Player as a menu that
  opens upward), landing not-found with Try again and an upload that opens the match, drops on
  the landing and on Player (wrong match, not `.dem`, the right one), progress under a throttled
  link while the summary plays, Cancel, a corrupt parse, expired, and the backoff.
- The real 504 MB replay of 129738985 (`MAPCRO_REAL_DEM`, skipped without it): picked from the
  landing's not-found notice with deadlock-api unreachable, uploaded with the bar at 23% · 119 /
  504 MB, parsed by the real worker in 4.8 s, shown as the full replay.
- Mutations: the drop handler not handing the file on, the landing opening a board for an
  unknown match, and Player not setting the not-found notice (and its wording) each fail the
  suite. The drop's own `.dem` check survives as an equivalent mutant: the landing's and
  Player's handlers refuse the same files with the same line.
