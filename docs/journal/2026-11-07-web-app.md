# 2026-11-07: the web app

The engine, sync, server and client core were done and tested; what was missing was a UI you
could use. This entry follows the app as it's built, one slice at a time.

## Slice 1: the tracer bullet

**Built:** a landing page that makes a board, the join card, the minimap renderer (from the
server's asset pack, or a schematic fallback), hero tokens you drag with the Move tool, and a
`just dev` loop. Stack, as decided: SolidJS + Vite + TypeScript, no component library, the
design's own CSS ported over.

### Surprises

- **The server refused the extractor's packs.** `pack.json` schema 2 writes
  `game.client_version` as a number; the server expected a string, so it skipped the pack with a
  log line and served nothing. The fix accepts either and still serves a string. The server test
  now writes one of its synthetic packs in the new shape, so it fails if this regresses. Schema 3
  (top-bar art) landed during the slice and loads unchanged.
- **The pack has less than the design assumed.** Lane ziplines come as node positions without
  tangents, so the app draws a smooth curve through them (Catmull-Rom). Camps carry no strength,
  so they all get the medium icon except the vaults, which say so in their names. There are no
  shops or powerups yet. The renderer skips kinds it doesn't know rather than guessing.
- **One class name hid the whole map.** The app marked a minimap that has pack art with the class
  `art`. The ported design CSS already had a rule `.art { display: none }` for its own art
  layers. The test checked that the terrain's background image came from the pack, and it
  did, so the test passed while the map was invisible. The screenshot caught it, not the test.
  The class is now `pack-art`, and the test also checks that the map is visible and has a size.
  Lesson: assert what the user sees, not only what the code set.
- **Playwright came up cleanly from nix.** `playwright-driver.browsers` is 1.59.1, and npm's
  `@playwright/test@1.59.1` matches it. The dev shell sets `PLAYWRIGHT_BROWSERS_PATH`, so nothing
  downloads browsers.

### Decisions

- **Fallback map data.** With no pack, the board still draws every objective, camp and lane in
  the right place. The positions come from our own derived data in `design/shared/minimap-data.js`
  (coordinates, no art). A script turns that data into the same entity list a pack carries, so
  one code path renders both.
- **The transform is a pure module** (`web/src/map/transform.ts`), with unit tests pinned to the
  README's numbers: the Amber west guardian lands at (119.05, 586.31) and the mid boss at the
  centre. A base guardian sits at the midpoint of its pair, and the Sapphire view mirrors through
  the centre.
- **The join card shows once per board per device**, prefilled with the remembered name.
- **The hero picker** is a small select in the roster. The design lists it as the one control
  that has to live off the map. It's in slice 1 so the real-pack screenshot shows portraits.
- **The e2e tests run against the production shape:** the real server binary serves the built
  client from `dist/`, on one origin, so the CSP and the Origin check are exercised too.

### What the tests cover

- `web/test/map.test.ts`: the transform, markers, tints, lane curves, and pack versus fallback.
- `web/e2e/board.spec.ts`: two browsers on the real server. One creates and joins a board, then
  drags a hero. The other sees `Coach · moving` mid-drag, and then the drop. The position
  survives a reload and opens on a third, fresh device. The Sapphire flip mirrors the position.
  A view link can't move anything.
- `web/e2e/pack.spec.ts`: a synthetic pack (generated 1×1 PNGs, never game art) drives the
  terrain, markers and portraits. With `MAPCRO_SHOT_PACKS` set, it also screenshots the real art.

## Slice 2: the scene strip

**Built:** the strip under the map. Each card is a lite minimap of its scene with the players as
dots. Click a card, or press ← →, to flip. **Add scene** puts a new scene after the current one.
Drag a card to reorder. The clock and the scene name are edited in place in the stage header
(click, type, Enter).

### Decisions

- **A new scene starts where the current one ends.** It copies the players (position, alive,
  souls, ult) and the objective states, but not ink, arrows or callouts. A play's next frame
  usually starts from the last one; the drawings belong to the frame they explain. It's one
  transaction, so one undo removes it.
- **Scene order keys are minted in the browser.** `web/src/core/order.ts` ports
  `OrderKey::between` from the Rust schema, and its test reuses the Rust test's cases, so
  every key the client sends validates on the server.
- **"8" means 8:00.** A bare number in the clock is minutes, because people say the time that
  way. A clock that doesn't parse ("8:75") keeps the editor open in red and sends nothing.
- **Which scene you're on is yours.** Flipping changes only your view (spec §4a). Others see your
  avatar on the card you're looking at, through presence `scene`.

### What the tests caught

- **A second minimap broke the slice-1 tests.** The card thumbnails are minimaps too, so
  `.mm-host` matched several elements. Playwright's strict mode refused to guess. The tests now
  scope to `.mapbox`, and the thumbnails' overlay is classed `mini`, as in the design, rather
  than `map`.
- **The report screenshots now go to `web/shots/`** (git-ignored). Playwright clears
  `test-results/` on every run, so the slice-1 shots were gone by the time the lead looked.

## Slice 3: the in-game top bar

**Built:** the game's top bar above the map, ported from `design/shared/topbar.js`. It has hero
portraits from the pack's top-bar art (schema 3), souls under each portrait, team totals beside
the clock, and each player's ult ring. There are no health bars, because the board doesn't
track health. All of it is edited in place:

- Click a souls number or the clock to type. "9040", "9k" and "9.0k" all work.
- Drag around a ring to set the cooldown, clockwise from 12 o'clock. Scroll on it for 5% steps.
  A click marks the ult ready.

### Decisions

- **A burst of scroll ticks is one edit.** The ring previews locally, then sends one op 350 ms
  after the last tick. Undo then takes the whole scroll back in one step, the same as a drag.
- **Untracked ults stay hidden from viewers, as in game.** Editors see a faint dashed ring they
  can click.
- **Viewer's team on the left.** The bar follows your own viewpoint, so the Sapphire flip also
  swaps the bar.

### What went wrong, and what caught it

- **Solid's `class` and `classList` fight.** When an element has a dynamic `class` and a
  `classList`, an update to `class` replaces the whole class attribute and wipes what `classList`
  added. The Sapphire team total lost its `right` class, so both totals sat in the same spot and
  only one showed. The lead spotted it in the screenshot; no test had checked it. The same bug
  was waiting in the minimap: flipping the viewpoint rewrote `class` and could have dropped
  `pack-art`. Every element now builds one class string with a small `cx()` helper. Two new
  checks would have failed before the fix: the totals mustn't overlap, and the map keeps its art
  after a flip.
- **The first ring-drag test started outside the ring.** It pressed 20 px above a 17 px ring, so
  nothing was grabbed. The test was wrong, not the app: the design says to drag *around the
  ring*, starting on it.

## Slice 4: the tools

**Built:** the tool picker under the map. The tools are Move (V), Draw (D) with the
seven-colour palette, Arrow (A), Callout (C), Laser (L) and Erase (E). Beside them are Clear ink
and per-person undo and redo (Ctrl+Z, Ctrl+Shift+Z or Ctrl+Y).
- Move also clicks objectives through active → destroyed → hidden. Viewers don't see hidden
  objectives; editors see them as faint ghosts, so they can click them back.
- Callouts drag with Move and edit on a double-click. While someone drags or edits a callout,
  everyone else sees their name tag on it.
- A view link's picker is Look and Laser, as on the phone artboard.

### Decisions

- **Every gesture is one transaction.** A whole erase scrub is one transaction of deletes;
  Clear ink is one, with Undo in its toast. A drawn stroke is one create, simplified (RDP) to fit
  the schema's 512 points.
- **The laser is presence only, timed by its sender.** The sender keeps timestamped points, holds
  them 0.7 s, fades them over 0.5 s, and resends as they expire. Receivers just draw the trail
  they're sent, tail faint and head solid. A reload shows nothing, because nothing was saved.
- **Arrows take a team only from a hero.** An arrow started on a token gets that hero's team;
  anywhere else, it's a neutral brass arrow.
- **Erasing hits a wider invisible path** under each stroke and arrow. Six-unit ink is too thin
  to scrub reliably otherwise.

### What the tests caught

- **Pointer capture swallows double-clicks.** A drag captures the pointer on the map's SVG, so
  the callout under the pointer never receives `dblclick`. The test caught it, and the callout
  now counts its own second tap.
- **A flat laser looks hidden.** A horizontal trail has a zero-height bounding box, and
  Playwright treats a zero-size element as invisible, so the first laser assertion failed while
  the laser was on screen. The test gesture is now diagonal. A test about the test, but worth
  knowing.

## Slice 5: presence and follow

**Built:**
- **Cursors:** everyone on the same scene sees everyone's cursor, viewers included.
- **People list:** shows what each person is doing (presenting, following someone, moving,
  laser), with one-click Follow for editors, "view only" for viewers, and a Name button for you.
- **Header:** a follow chip says "Following Coach · Stop", or "Coach is presenting · Follow F"
  when you aren't following. Whoever is followed sees a "Presenting · n following" pill.
- **Pan and zoom:** wheel to zoom about the pointer, and drag the empty map with Move or Look to
  pan.
- **Following:** it mirrors the presenter's scene and viewport. Flipping a scene, panning or
  zooming stops it, and a toast says why, with **Follow again**.

### Decisions

- **There's no "start presenting" button.** You're presenting when someone follows you. That's
  enough for the coaching flow, and it keeps the presenter from having any control over
  followers, as the spec wants.
- **The viewport travels as a world centre and zoom**, so a Sapphire-side follower sees the same
  part of the map as an Amber-side presenter, mirrored. A round-trip test pins it.
- **Flipping the viewpoint doesn't stop following.** It changes which way up the map is, not
  where you're looking. The spec's list is scene, pan, zoom and floor.
- **A presenter who leaves ends the follow**, and the follower is told.
- **Tokens, name tags and cursors keep their screen size when you zoom**, like the HUD's
  markers. The ink and arrows zoom with the map, because they are drawn on it.

### What the tests caught

- **Viewers couldn't pan.** The gesture handler returned early for anyone without edit rights
  before it reached the Move/Look branch, so a viewer's drag did nothing. The follow test failed
  on "panning stops following" for the viewer. Look now handles panning before the editor check.

## Slice 6: share and clone

**Built:**
- **Share dialog** (owners and editors): label a link, pick View only or Can edit, and create
  it. The new URL shows once, with a "this link is the key" warning that matches its role.
  Below it is the list of links as a tree: the owner sees every link, and an editor sees the
  links it made and the ones shared from them. The dialog has no revoke button; its footer
  points to **Clone to a new board**.
- **Clone dialog** (anyone, viewers included): pick a title and see what comes along and what
  stays behind. Cloning lands you on the copy as its owner, with a "You own this copy · Share"
  note.

### Decisions

- **Copy is offered only for links this device made.** The server stores only hashes of tokens,
  so an old link's URL can't be fetched again. The browser keeps the tokens it minted (in
  `localStorage`, by board) and offers Copy for those. Other rows show their label and role
  only. This is the honest version of the design's Copy-on-every-row.
- **"N people on it now" isn't shown.** The server doesn't say which link each connection
  uses, and inventing a count would mislead.
- **Your own link isn't a row.** The browser works out its own link id the way the server does
  (the first 16 hex digits of the token's SHA-256), so it can leave itself out and mark "Made by
  you". A unit test pins it to the server's format.
- **The clone skips the join card.** You just said who you are on the original.

### What the screenshot caught

- **The map's flip button floated over the dialog.** It sits at z-index 30, and the dialog's
  backdrop was at 10. The backdrop now sits above everything on the board.

## Slice 7: the phone

**Built:** below 700 px wide, the board switches to the phone layout from `phone-following.html`.
Top to bottom:
- a header with your role and side;
- the follow banner (Following X · Stop, or X is presenting · Follow);
- the scene title with its clock;
- the compact top bar;
- the map, with a small Look/Move, Laser and Flip picker on it;
- callouts as numbered pins, with their text listed under the map, and the scene note;
- Prev and Next with dots. You can swipe the title or the nav to flip.

The desktop also got its **Scene note** editor in the side panel, so the phone has something to
show.

### Decisions

- **One component, two layouts.** The phone isn't a separate app. The same state, map, layers,
  top bar and follow logic render into a different shell. The map, the toast and the overlays
  are shared pieces.
- **The phone's picker is Look (or Move, for editors) and Laser.** The other tools switch back
  to Move on a phone. Drawing on a 390 px map with a thumb isn't a good experience, and the
  design shows only these two.
- **Callouts are numbered pins on the phone.** Label boxes would cover the map at that size.
  Pins and list share one order (by record id), so pin 2 is always line 2.
- **The scene note saves when you leave the box.** The spec's text splice ops (§3) aren't in
  the schema yet; the note uses the `NoteText` set that exists. Two people typing in the same
  note at once would lose one person's words. That's the open question Q2.

### What the tests caught

- **The phone test pointed at the desktop map.** The map helper in the tests looked for
  `.mapbox`, which the phone doesn't have. Every helper now finds the map by its test id.
- **A hidden button that wasn't.** The desktop flip button carried `hidden` on the phone, but
  the design CSS gives it `display: grid`, which beats the browser's default for `hidden`. The
  screenshot showed it, and the phone test now checks it's hidden.
