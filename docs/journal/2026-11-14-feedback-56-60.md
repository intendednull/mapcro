## Why two releases

Three of the items change what a log may hold, and a cold load re-validates every logged
transaction. The v10 server (e878c30) rolled back to would refuse:

| Item | New in a log | v10 on replay |
| --- | --- | --- |
| #56 | a scene name of 25–48 characters | `TextTooLong` |
| #59 | `FieldValue::CalloutSide`, `Callout.side` | can't parse the field value; drops a record's `side` |
| #60 | `FieldValue::StrokeColor` | can't parse it |

So release 1 reads them and takes none from outside; release 2 writes them. Recolouring an
**arrow or a comment** needs no reader: `ArrowColor` and `CalloutColor` are field values v10
already takes (no client ever sent one). They ship with #60 in release 2 anyway, so the feature
arrives whole.

## Release 2 (after the lead deploys release 1): the writer

Order matters:

1. `justfile`: `reader := "<the deployed v11 commit>"`. Run `just rows-lock` on that commit as
   usual.
2. `map_state.rs`: the three statuses to `Status::Live`. `store.rs`: the writer's step.
   **Its version number is the lead's to give at merge** (2026-11-14): map-state's D2 reader
   (row `has_heroes`, `Ahead`) is queued too, and whichever of that reader and this writer is
   ready first takes v12, the other v13. So write it with the number in one place:
   - **The floor is 11 whichever number it gets.** Today `Step::NeedsReader` sets the floor
     to `from`, the version just before the step: right when the reader is the step before
     (8 → 9, 9 → 10), wrong if D2's reader takes v12 and this writer v13 (the floor would be
     12, and a rollback to the v11 build, which reads everything this writer stores, would be
     refused). Make the step carry its reader: `Step::NeedsReader { reader }`, floor
     `floor.max(reader)`; steps 8 and 9 become readers 8 and 9 (the same floors as today, held
     by the existing tests), and this one is `reader: 11`. The lead approved this form, to be
     made in this release by this stream (2026-11-14); map-state's D2 writer will use it too,
     with D2's reader's number.
   - One constant for the writer's version (say `SIDES_WRITER: i64`), used by `step()`, the
     `migrate` arm and the tests; `SCHEMA_VERSION` is at least it. Changing the number is
     that line (and `SCHEMA_VERSION` if this is the newest step).
   - Tests by the constant, not the literal: a database at the writer's version has floor
     11; the v11 build opens it and v10 doesn't; if a reader step sits between (D2's at v12,
     additive), the floor is still 11 after both. Replace
     `the_v11_reader_stores_nothing_new…`'s "statuses are `Ahead` while v11 is the newest"
     with "statuses are `Live` only from the writer's version on".
   - `docs/deploy.md`: the rollback target from the writer's version is the v11 build
     (and D2's reader, if it is in between), nothing older.
3. `admission_characterisation.rs`: the third test and the scene-name half of the first now

## Sequencing with the other branches

- **Store versions**: this takes v11 (release 1). The writer (release 2) takes v12 or v13,
  whichever map-state's D2 reader doesn't; the lead assigns it at merge. Its floor is 11
  either way (step 2 above). A reader step from another branch can sit between this reader and
  this writer; a writer step can't share a version with a reader it needs.
- **`Admit` grew three fields**: every `Admit { … }` literal in tests now ends
  `..Admit::AHEAD`. A branch that adds a literal the old way won't compile after the merge.
- **`Callout` grew `side`**: literals need `side: Default::default()`.
- **`Board.tsx`**: only the sidebar block and the `sideTab` signal changed.
- **Phone transport** (`mobile-defaults`): `.pl-speed` is now a group of two buttons and the
  speed, wider than the list was. The class and its grid area are unchanged.
