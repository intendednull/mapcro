# UX pass — 2026-11-09

Scope: first-time and coaching-session workflows. Branch `ux-pass`. Read architecture spec,
backlog and November 9 journals before review. Findings below exclude known backlog items.
Screenshots stay in `/tmp`, never committed (may contain game art).

## 1. Replay selection skipped by keyboard — medium

- **Where:** landing → Load a game → Select replay file.
- **Problem:** the visible control is a label with a hidden file input. A real Chromium Tab pass
  on production went from Match id directly to Open match; there is no keyboard stop to select a file.
- **Impact:** keyboard users cannot take the primary upload path, particularly before they know a
  match id. The fallback upload button only appears after certain lookup failures.
- **Suggested fix:** use a native button to invoke the hidden input, keeping selection and submit
  as separate actions. Add a test for Tab focus and Enter opening the chooser.
- **Status:** fixed with a native button. `landing-keyboard.spec.ts` passes against the local
  built client; it checks Tab focus, Enter opening the chooser and the selected filename.

## 2. Phone owners cannot access Share — medium recommendation

- **Where:** joined local owner board at 390×844 (`Board.tsx` phone layout).
- **Problem:** desktop exposes Share and Clone in the header; the phone header exposes neither.
  Chromium found zero Share buttons after joining. The phone has scene navigation but no menu
  providing these actions. Screenshot inspected: `/tmp/ux-board-phone.png`.
- **Impact:** someone starting a board on a phone cannot mint a view link for their coaching
  partner through the UI. Copying the address instead shares the owner's token.
- **Suggested fix:** add a compact board-actions menu with Share for eligible roles, reusing
  the existing dialog. Check phone dialog fit and keyboard access. Decide separately whether
  Clone and profile belong there. This is a recommendation, not implemented.

## 3. Board-creation failure gives no recovery guidance — low recommendation

- **Where:** landing → Start fresh → New board.
- **Problem:** a simulated local HTTP 503 produces only “Failed”. Screenshot inspected:
  `/tmp/ux-create-error.png`. Match-opening failures already say “Failed. Try again.”
- **Impact:** a first-time visitor cannot tell which action failed or whether retrying is useful.
- **Suggested fix:** say “Couldn't create the board. Try again.” and announce the error with
  `role="alert"`. Keep the title intact. Add an e2e case for failed creation followed by retry.
- **Status:** recommendation only; avoid changing other error surfaces without reviewing them.
